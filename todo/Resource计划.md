## 一、开工前要定死的

| # | 要定什么 | 谁定 | 不定会怎样 |
|---|---|---|---|
| 1 | 缓存 TTL 具体天数 | 用户 | 清理逻辑写不出来 |

## 二、实现顺序（每步单独可验收）

| 阶段 | 做什么 | 怎么验收 |
|---|---|---|
| 1 | 项目骨架：走 `Global.cs` 的通用入口；边界检查改成**按 `target` 走** | 服务能起来；越界拒绝话术正确；远端路径不被误拦 |
| 2 | 寻址：`target` + `path` 解析（空 = 本地 / 带前缀 = 会话 / 其余 = 包） | 三种 target 各一条用例；**认不出来必须报错、不降级到本地** |
| 3 | 凭据：全文读产 `cookie`；写前重读比对；无凭据只出**影响清单** | 覆写缺凭据被拦、对不上被拒、成功后返回下一个凭据；两种情形都**不标 `isError`** |
| 4 | 本地：读 / 列 / 写 / 删（回收站）/ 移（跨卷判断） | 基线第五节那张表逐行过 |
| 5 | 缓存：三类条目、命中不发凭据、`cache=false`、启动时**异步**清理 | 命中只给 `key`；写结果不命中；下载只留元数据；清理不阻塞启动 |
| 6 | 远端（FTP）：`login` / `logout` + 统一寻址落到会话 | 覆盖上传要凭据；不带会话只能注销；日志里密码打码 |
| 7 | 压缩包：包内读、包凭据 + 对象凭据 | 包内写要两个凭据（`containerCookie`） |
| 8 | `browse`：JS 渲染 + 人机验证 | 第五节第 3、4 条定完才开工；结果不进缓存 |

## 三、怎么算做完

- `dotnet build ZMS.MCP.slnx` 0 错 0 警告；`dotnet test ZMS.MCP.slnx` 全过。
- **每个工具一条"三态"用例**：缺凭据 / 凭据对不上 / 成功。
- 一张「痛点 → 工具 → 测试」对照表（对齐基线末尾的附表）。
- 单测覆盖：`target` 解析、凭据比对、缓存三类条目、边界检查按 `target` 走。

## 五、有意不做 / 已知缺口

（承接基线第七节，施工时别顺手"补上"）
