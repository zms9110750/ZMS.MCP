# ZMS.MCP.Resource 工具手册 v1

这份手册以**实机调用结果**写成：15 个工具的参数取自运行时 schema，返回值示例是把 MCP server 真跑起来调回来的原文（不是从代码推断的）。

它管的是**文件系统与网络上的东西**：本地文件 / 目录、压缩包、FTP 会话、HTTP、浏览器。跟 `docs/ZMS.MCP.Csharp.md`（管 C# 符号）、`docs/ZMS.MCP.Structured.md`（管配置文档的结构）是三件不同的事。

**一句话讲清它的性格**：每个写操作都问一句"你确定吗"，而问的方式是**凭据**（cookie）—— 你读过、我看过，才准动。

## 约定

- 参数类型用 C# 可空语法：`string` = 必填；`string?` = 可空（默认 `null`）。
- **返回恒为 markdown 文本**，不是 JSON。
- **失败形态统一**：第一行以 `Error: ` 开头、协议层 `isError=true`。**缺凭据不是失败**——那是两段式的第一段，`isError=false`。
- **工作区边界**：只有 `ZMS_MCP_WORKSPACE` 里的目录（多个用 `;` 分隔；没设就用进程当前目录）才准动。越界会被拦：

````
Error: 路径不在本次会话的工作区里：X:\temp\zms-doc
  工作区：C:\Users\16229\source
  要动它的话：让宿主把这个目录加进去（环境变量 ZMS_MCP_WORKSPACE，多个目录用 ';' 分隔），或者明确告诉我你确认要越界 —— 我不替你猜。
````

### 寻址：`target` + `path`

| `target` | 含义 | `path` 是什么 |
|---|---|---|
| 空 | 本地文件系统 | 绝对路径（可带盘符） |
| `ftp:<session>` | FTP 会话（来自 `login`） | 远端纯路径 |
| 压缩包路径（`.zip` / `.7z` / `.tgz` / `.ztsd` …） | 压缩包 | 包内纯路径（`/` 分隔） |
| **追踪 cookie**（来自 `track_archive`） | 正在被追踪的压缩包 | 包内纯路径 |

**认不出来就报错，绝不降级到本地**——一降级就会落到同名的本地文件上。另外一个有用的推论：**只要 `target` 不是空的，`path` 就是那个容器里的路径**，所以工作区边界只查 `target` 为空时的 `path`。

### 凭据（`cookie`）

改到**已经有东西**的对象时要带上它。它是**两段式**的：

- **元数据段**（16 位十六进制）：路径 + 大小 + 修改时间。只要没读内容，凭据就只有这一段 —— `list` 指到一个文件时给的就是它。
- **内容段**（`-` 后面再 16 位）：读过全文才加上，算的是内容 + 编码。

两段分开，是为了让**两档凭据能互相校验**：比的时候元数据段必须一致，**两边都有内容段时**内容段也必须一致。所以"只 list 过"拿到的凭据，也验得过一个读过全文的人给的凭据。

**修改时间进了元数据段**：哪怕内容一字没动，只要被人改过，凭据就对不上。

读过全文（两段）：

````
# X:\temp\zms-doc\笔记.txt
- 编码：utf-8
- 字符数：12
- 凭据：`d5740d73af7c30e9-2554c6226e42a70c`
````

只看过元数据（一段）：

````
- 凭据：`d5740d73af7c30e9`
````

**它防的是手滑，不是恶意**：不存任何状态，纯算出来的，可以伪造。

## 一、读取

### 1. 读内容 `read`

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 要读的对象 |
| `target` | `string?` | 在哪个存储/容器上读；空 = 本地 |
| `skipline` | `int` | 先跳多少行（**先于 `offset` 执行**）；默认 `0` |
| `offset` | `int` | 再跳多少字符 |
| `length` | `int` | 至多给多少字符；默认 `0` = "没带范围"（**带范围读**而没给 `length` 时，按 `5000` 字符算） |
| `takeline` | `int` | 至多给多少行 |
| `encoding` | `string?` | 按什么编码解；空 = BOM → 严格试 UTF-8 → 拒绝 |
| `regex` | `string?` | 在内容里搜；命中按数量分级给上下文 |

**完整读**给凭据，**带范围读**不给（只读一段 = 没看过全貌）：

````
# X:\temp\zms-doc\笔记.txt
- 编码：utf-8
- 字符数：12
- 凭据：`d5740d73af7c30e9-2554c6226e42a70c`

```
第一行
第二行
第三行

```
````

````
# X:\temp\zms-doc\笔记.txt（带范围读）
- 编码：utf-8
- 全文 12 字符
- **只读了一段 → 不给凭据**（不算看过全貌）

```
第一行
第二行
```
- 范围内还有 0 字符未给出（范围共 7 字符）
````

**超过单次交付上限（16000 字符）**——只有这一种情况会让"完整读"也拿不到凭据：

````
# X:\temp\zms-doc\大日志.txt
- 编码：utf-8
- 字符数：40492
- 全文共 40492 字符，这里只给前 16000 字符。
- **没交付完整份 → 没有凭据**：不能改，也不能删。
````

`regex` 的命中分级：`>20` 只给行号；`>5` 给上下 1 行；`≤5` 给上下 3 行：

````
命中 1 处（每处上下 3 行）
- 2:
    1: 第一行
    2: 第二行
    3: 第三行
    4: 
````

- 之前：想确认"这份内容现在是什么样"，或者拿一个凭据去改它。
- 之后：要改就用 `write` / `replace`。
- 不能做：不写盘；解不出来宁可报错，**不静默替换成 `U+FFFD`**。
- 注意：读压缩包里的条目时，标题写成 `<包路径>!<包内路径>`，凭据是**那个条目自己**的。

### 2. 列清单 `list`

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 目录、压缩包、**也可以是一个文件** |
| `target` | `string?` | 空 = 本地 |
| `depth` | `int` | 递归深度；`0` = 只当前文件夹（默认） |
| `limit` | `int` | 每层最多几条；`0` = 按层递减（200 / 100 / 50 / 20），上限 200 |
| `type` | `string?` | 只列 `file` 或只列 `dir` |
| `meta` | `string?` | 逗号分隔的属性名，只认 `created` / `modified` / `size` / `count` |
| `regex` | `string?` | 条目名过滤 |

**完全穷举**才给目录树凭据（没被 `depth`/`limit` 截断，输出也没超 16000 字符）：

````
# X:\temp\zms-doc
- 类型：目录

大日志.txt
笔记.txt

- 目录树凭据：`b85f8db746bdae59`
- 条目总数：2
- 总大小：105522 字节
````

被截断就没有：

````
# X:\temp\zms-doc
- 类型：目录

多处.txt

- **被截断了 → 不给目录树凭据**（凭据只在完全穷举时才给）
````

**指到一个文件**：只给元数据，而**这里就能拿到它的凭据**（覆盖它、删它够了）：

````
# X:\temp\zms-doc\笔记.txt
- 类型：文件
- 大小：30 字节
- 修改时间：2026-10-04T23:02:15.1624410Z
- 创建时间：2026-10-04T23:02:15.1614503Z
- 凭据：`c396227e9c339b1b`
（只看了元数据，没有读内容 —— 覆盖它、删它，有这个凭据就够。）
````

**指到压缩包**（一个包就是一棵树）：

````
# X:\temp\zms-doc2\成品.zip（压缩包）
- 路径：/
- 里面 1 条

- 放进去/素材.txt  [27 字节, 2026-10-05T07:10:58.0000000+08:00]
  cookie: `ff307701932af79d`

- 要动里面哪一条，就带**它自己**的 cookie（`copy` / `delete` 走拟定）。
````

## 二、写入

### 3. 写 `write`

只管**新建**与**覆写**；改已有内容里的某几处用 `replace`。

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 目标 |
| `content` | `string` | 整份内容 |
| `target` | `string?` | 空 = 本地；`ftp:<session>` = 远端 |
| `encoding` | `string?` | 写回编码；空 = 用读它时的编码，新建 = UTF-8 无 BOM |
| `cookie` | `string?` | 覆写已有对象时必填；新建不要 |

**新建**不要凭据：

````
# 已写入（新建）
- X:\temp\zms-doc\新文件.txt
- 大小：15 字节
- 编码：utf-8（无 BOM）
- 下一个凭据：`5bcdbbdaa5a8c707-4ca7ae2d4a5d3035`
````

**覆写但没给凭据**——不执行，出影响清单（**不算失败**）：

````
# 会发生什么（未执行）
- X:\temp\zms-doc\笔记.txt
- 目标已有内容：30 字节，改于 2026-10-04T23:02:15.1624410+00:00
- 这次会把整个文件覆盖掉。
- 要执行，先读它拿凭据（现在是 `c396227e9c339b1b-2554c6226e42a70c`）。
- （这不算失败：缺凭据是两段式的第一段。）
````

**凭据对得上**：

````
# 已写入
- X:\temp\zms-doc\笔记.txt
- 大小：9 字节
- 编码：utf-8
- 下一个凭据：`fa122fb8a89a49c0-2d3558cde57a0bfa`
````

**凭据对不上**（这期间被改过）——不执行：

````
# 没执行：凭据对不上
- X:\temp\zms-doc\笔记.txt
- 你给的：`c396227e9c339b1b-2554c6226e42a70c`
- 现在算出来：`fa122fb8a89a49c0-2d3558cde57a0bfa`
- 现状：9 字节，改于 2026-10-04T23:02:15.4084598+00:00 —— 这期间它被改过。
- 重新读一次，基于最新内容再来。
````

**打到远端**：只做「目标还不存在」这一种。远端重叠写需要凭据，而**远端读取不发凭据**，所以那种工作直接拒绝：

````
# 没执行：远端已经有这个文件
- ftp:s1a2b3c4d（anonymous@example.com:21） /remote/a.txt
- 远端重叠写属于「需要凭据的工作」，而远端读取不发 cookie —— 拿不到它的凭据，做不了，请用户手动处理。
````

**打到压缩包上**：不走 `write`（包里的改动要经由拟定）：

````
Error: 压缩包内的改动不走 write：往包里放东西用 `copy`（目标填追踪 cookie），删条目用 `delete`。
````

### 4. 替换 `replace`

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 目标 |
| `pattern` | `string` | 要匹配的内容；`regex = true` 时是正则 |
| `replacement` | `string` | 替换成什么；正则时可引用捕获组（`$1`、`${name}`） |
| `cookie` | `string` | **必填** |
| `target` | `string?` | 空 = 本地 |
| `regex` | `bool` | 是否把 `pattern` 当正则；默认 `false` = 按字面 |
| `encoding` | `string?` | 写回编码 |

**命中一处**：

````
# 已替换
- X:\temp\zms-doc\笔记.txt
- 大小：18 字节
- 编码：utf-8
- 下一个凭据：`cdf29c2fd083d1a2-24c88147366ec6d5`
````

**命中多处**——不执行：

````
# 没执行：命中多处
- X:\temp\zms-doc\多处.txt
- 命中 3 处。收紧匹配（或打开 regex 用更精确的写法），再来一次。
````

**没命中**——报错，**不自动创建**（注意 `isError=true`）：

````
Error: 没命中：没有这个词（不自动创建）
````

## 三、删除与搬动

### 5. 删 `delete`

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 要删的对象 |
| `cookie` | `string` | **必填**（删目录时是"读整棵树"那份；删包内条目是那个条目自己的） |
| `target` | `string?` | 空 = 本地；压缩包路径/cookie = 包内条目 |

**一律走回收站**：

````
# 已删除（回收站）
- X:\temp\zms-doc\搬过去.txt
- 去回收站能找回来。
````

**进不去回收站**（过大装不进、网络盘、可移动盘、只读卷）——**不执行**，交用户手动：

````
Error: 进不了回收站，所以没有删：<原因> —— 这个操作交给用户手动处理（不做硬删）。
````

**远端**——一律拒绝（远端没有回收站）：

````
Error: 远端删除一律不执行（远端没有回收站，删了不可恢复）——请用户手动处理。
````

**凭据对不上**：

````
# 没执行：凭据对不上
- X:\temp\zms-doc\搬过去.txt
- 你给的：`0123456789abcdef`
- 现在算出来：`75a487b7dfa39c98`
- 重新读一次（`read` / `list`）拿新凭据，再来。
````

### 6. 移 `move`

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 源 |
| `toPath` | `string` | 目标 |
| `target` | `string?` | 源在哪；空 = 本地 |
| `toTarget` | `string?` | 目标在哪；空 = 本地 |
| `cookie` | `string?` | 源那一侧的凭据（跨卷 / 跨存储 / 删源时要用） |
| `toCookie` | `string[]?` | 目标那一侧的凭据（合并文件夹、覆盖文件） |

**目标空着**：

````
# 已移动
- 源：X:\temp\zms-doc\副本.txt
- 目标：X:\temp\zms-doc\搬过去.txt
````

**目标已有内容**——不执行，先做目录验证（输出见 `copy` 那一节，两者同一套）。

**压缩包里的移动**——拆两步：

````
Error: 压缩包里的移动请拆成两步：`copy` 到包里 + `delete` 掉原来那个（两者都走拟定）。
````

**远端**：只有**本地 → 远端**能做（删的是本地源、走回收站）。远端删除是拒绝的，所以反向与"远端→远端"都报错。目标远端非空也拒绝（要凭据而远端发不出）。删本地源要源那份凭据，没给就先出影响清单。

### 7. 复制 `copy`

跨存储搬东西就用它：**FTP → 本地是下载，本地 → FTP 是上传。**

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 源 |
| `toPath` | `string` | 目标 |
| `target` | `string?` | 源在哪 |
| `toTarget` | `string?` | 目标在哪（可以是**追踪 cookie**，往压缩包里放东西） |
| `toCookie` | `string[]?` | 目标那一侧的凭据，**顺序无关** |

**目标不存在**：

````
# 已复制
- 源：X:\temp\zms-doc\笔记.txt
- 目标：X:\temp\zms-doc\副本.txt
````

**目标已有内容**——先做**目录验证**：会合并的文件夹、会被覆盖的文件，**各要它自己的凭据**，没给就拒绝：

````
# 目标已有内容（未执行）
- 源：X:\temp\zms-doc\笔记.txt
- 目标：X:\temp\zms-doc\副本.txt

## 会被替换的文件（1 个）
- X:\temp\zms-doc\副本.txt
  cookie: `ff333472691abfa6`

- 还缺这个对象的凭据：X:\temp\zms-doc\副本.txt

请确认意图；如果确认，就用上面这些 cookie 再来一次（`toCookie` 顺序无关）。
````

冲突分档：**>15** 带上"建议由用户手动处理"；**>50** 不逐个列凭据，只报数量并声明 **「你无法从这个工具得到授权」**。

**往被追踪的压缩包里放东西**（`toTarget` 填追踪 cookie）：

````
# 拟定已更新
- 包：X:\temp\zms-doc2\成品.zip
- 这一条：增加 `放进去/素材.txt`（27 字节）
- 现在共 1 条拟定。
````

**跨存储且目标是远端、已经有东西**——拒绝（远端发不出凭据）：

````
# 没执行：目标在远端、已经有东西
- 目标（远端）：/remote/dir
- 会合并的文件夹：1 个；会被覆盖的文件：2 个
- 远端读取不发 cookie，拿不到它们自己的凭据 —— 这一类工作不能做，请用户手动处理。
````

## 四、网络

### 8. 取 / 下载 `fetch`

| 参数 | 类型 | 说明 |
|---|---|---|
| `url` | `string` | 必须 `http://` 或 `https://` 开头 |
| `method` | `string?` | 空 = `GET`；只认 `GET`/`POST`/`PUT`/`PATCH`/`DELETE`/`HEAD`/`OPTIONS` |
| `head` | `string?` | 请求头，JSON 对象字符串 |
| `body` | `string?` | 请求体 |
| `targetPath` | `string?` | 下载到哪个本地路径 |
| `cookie` | `string?` | 覆盖已有本地文件的凭据 |

常量：超时 `15` 秒、重试上限 `3` 次、响应截断 `16000` 字符；限流（**只作用于下载**）：额度 `10 MB`、每分钟恢复 `1 MB`。

**不给 `targetPath`（取内容）**——**全额进缓存**并给 `key`，哪怕交付被截断（http 没有偏移，截断了后半段就再也要不到，只有缓存里留着完整的）。

**`HEAD` 是例外**：那种请求不回正文，所以**不给 `key`、也不进缓存**，改列响应头。

````
# GET http://localhost:18573/text
- 状态：200
- 全文 12 字符，这里给 全文
- key：`efb6ef1b-bf94-4a3b-80bf-1e8da52ca3b1`
- 要看后半段：用 `cache(key=..., path=...)` 落盘，再用 `read` 的范围参数读它。

```
本地服务返回的一小段文本
```
````

被截断时那一行变成：`- 全文 30000 字符，这里给 前 16000 字符`。

**给了 `targetPath`（下载）**——落盘，**不进内容缓存**（只留一条元数据记录），而且这一路受额度约束：

````
# 已下载
- http://localhost:18573/text
- 目标：X:\temp\zms-doc2\下回来.txt
- 大小：36 字节（状态 200）
- 额度还剩：10.00 MB
- 原件已经在磁盘上了，去读原件（这条不进内容缓存）。
````

**拦截不做判定**：`2xx` 就是成功，判断交给调用方。

````
Error: url 必须是 http:// 或 https:// 开头的绝对地址：not-a-url
````

### 9. 缓存 `cache`

| 参数 | 类型 | 说明 |
|---|---|---|
| `key` | `string?` | 空 = **列缓存**；给了 = 取那一条 |
| `path` | `string?` | 给了（且给了 `key`）就落盘；目标必须不存在 |
| `page` | `int` | 列缓存翻页；默认 `0`，每页 `50` 条 |

常量：TTL `7` 天（到点删）、容量上限 `64 MB`（按最旧淘汰）、落点 `%LOCALAPPDATA%\ZMS.MCP\cache`（`ZMS_MCP_CACHE` 可覆盖）、取一条时一次最多 `5000` 字符。

**进缓存 ≠ 命中缓存**：进缓存的是**取回来的东西**——只有 `fetch` 取内容的正文进（`HEAD` 不进），
**本地文件不进**（原件就在盘上），**FTP 的读取也不进**。**命中一律不发生**——要用就来这里拿。

**列缓存**：

## 七、压缩包（走拟定）

压缩包**不造新工具**：读用 `read` / `list`，写用 `copy` / `delete`，落盘用 `confirm`。

**不追踪 = 只读**。查看**永远直读磁盘上现在那个包**，跟有没有在追踪无关；要改，先 `track_archive` 拿 cookie，再把 cookie 填进 `target` / `toTarget`。

### 13. 追踪 `track_archive`

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | `string` | 要追踪的压缩包，**可以还不存在**（那就是"要创建"） |
| `target` | `string?` | 空 = 本地。**FTP 上的压缩包追踪不了** |
| `format` | `string?` | 创建时的格式：`zip` / `7z` / `tgz` / `ztsd`。包已存在时忽略；不存在时必填 |
| `cookie` | `string?` | 传回追踪 cookie = **解除追踪**（连同拟定一起清掉） |

````
# 已开始追踪
- 包：X:\temp\zms-doc2\成品.zip
- 格式：zip（还不存在，落盘时创建）
- 追踪 cookie：`5bd79488-111d-4c44-ad96-defc9628a142`
- 现在攒了 0 条拟定。
- 之后 `copy` / `move` / `delete` 打到这个包上只会攒一条，`confirm` 才落盘。
````

````
# 已解除追踪
- 包：X:\temp\zms-doc2\成品.zip
- 清掉了 1 条拟定。
````

**为什么写要攒着**：改一个条目就得把整包重写一遍，攒起来一次做才划算。**包内改动要的是被涉及条目自己的凭据**（删它 / 覆盖它），不是"包的凭据"。

### 14. 落盘预检 / 落盘 `confirm`

| 参数 | 类型 | 说明 |
|---|---|---|
| `cookie` | `string` | 追踪 cookie |
| `applyCookie` | `string?` | 空 = **落盘预检**；给了 = **落盘** |

**预检**（不碰磁盘，把"落盘后会变成什么样"摆出来）：

````
# 落盘预检（X:\temp\zms-doc2\成品.zip）
- 格式：zip
- 攒了 1 条：增加 1 条，删除 0 条
- 合计大小：27 字节（落盘后要占这么多）
- 现在包里：0 条；落盘后：1 条

落盘后包里会变成：
```
  放进去/素材.txt  （新）
```

- 分档：正常（合计不到 50 MB）。

- 落盘 cookie：`98785c0b76a0702c`
- 确认无误就把这个 cookie 填进 `applyCookie` 再来一次。
````

**落盘**（重读磁盘比对 → 重放 → 攒出新包 → 原子替换）：

````
# 已落盘
- 包：X:\temp\zms-doc2\成品.zip
- 大小：170 字节
- 里面 1 条；拟定已清空（追踪还在，cookie 不变）。
````

常量与边界：合计 **> 1 GB 不给打**；**> 50 MB 先向宿主确认**（MCP 支持提问就走那条路，不支持就直接打）。**拟定期间包被人动过就拒绝落盘**（大小或修改时间对不上）。`ztsd` 是 **tar + zstandard**，SharpCompress 写不了，所以走它自带的 zstd 流自己包了一层。

## 八、区间抽取 `pick_random`

**这一节与"资源访问"无关** —— 它不读也不写任何东西。它是从被移除的老项目 `ZMS.MCP.Cli` 迁过来的
（那份项目里其余能力在四个新项目里都有对应，只这一项没有），来历写在 `plan/Resource/P-RS-08-区间抽取.md`。

`[McpServerTool(ReadOnly = true, Destructive = false, Idempotent = false, OpenWorld = false)]`

从 `名称:点数` 的池子里反复抽，直到抽出的**项数**落在给定区间、**点数和**也落在给定区间。

| 参数 | 类型 | 说明 |
|---|---|---|
| `expression` | `string` | 表达式：`(2,4)[5,8]{甲:3,乙:2,丙:4}`；两项各自相等时可写 `(3)[7]{...}`；池子也可来自 `{file://pool.json}` |
| `single` | `boolean?` | `true` = 不放回（抽过的项不再出现）；默认有放回 |

全角逗号与全角冒号也认（`甲：3，乙：2`）。

**实测输出**（`expression="(2,4)[5,8]{甲:3,乙:2,丙:4}"`）：

```
丙, 乙 = 6
```

约束抽不出来时（下一个点数落不到池子里任何一档）会报错并说清当时的约束，不会静默给个不满足的结果。

## 附录 A：这个工具为什么长这样

它管的是**位置与字节**：一个路径指向盘上的一个东西，一份内容是多少字节。所以它的核心问题不是"语义对不对"，而是**"我动它的时候，它还是我看到的那一份吗"**——凭据就是为这个来的。

因此它刻意不做的：不判断网络响应"是不是成功"（`2xx` 就算）、不替你猜越界意图（工作区外一律拒绝）、不在你看不清后果时硬干（没凭据就只出清单）。

## 附录 B：明确不做的

| 事 | 现状 |
|---|---|
| 拦截判定 | **有意不做**：`2xx` 即是成功，判断交给调用方 |
| 两个目录差在哪 | 没有（痛点清单里的这一半没接） |
| 远端覆盖 / 合并 | 拒绝——远端读取不发凭据 |
| 远端删除 | 一律拒绝（没有回收站） |
| 远端移动 | 只有"本地 → 远端"；反向要删远端，所以不做 |
| 压缩包内的 `write` / `replace` | 不做：改条目 = 删掉再放一个，走 `copy` + `delete` |
| FTP 上的压缩包 | 追踪不了 |
| 单文件元数据 | 没有独立工具，走 `list` 指到那个文件 |
| 并发保护 | 没有：凭据只能在**读-写之间**发现问题，拦不住**同时写** |
