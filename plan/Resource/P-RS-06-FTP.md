# P-RS-06 · FTP（`login` / `logout`）

| | |
|---|---|
| **项目** | `src/ZMS.MCP.Resource` |
| **痛点** | [F12](../F12-FTP够不着.md)、[F2](../改动的可信度.md)、[F4](../F4-不知道自己在哪层目录.md) |
| **状态** | 已实现 |
| **工具** | `login`、`logout`（远端读写挂在 `read` / `list` / `copy` / `delete` 上） |

## 摘要

登一次 FTP，拿到一个**会话句柄**，之后的文件操作把它带上：列目录、读文件、上传下载。
凭据只在内存里。远端的一切写操作都比本地更保守——尤其**删除一律不执行**。

## 现状

- 宿主**没有任何 FTP 能力**。要做只能在命令行里拼 `FtpWebRequest`：
  老 API、别扭，而且**中文文件名 / 被动模式 / 编码**全是坑。
- 为了一条命令，**用户名密码被写进对话里**（[F12](../F12-FTP够不着.md)）。
- 这些手拼的命令**不经过工作区边界检查**，也**没有凭据与确认**——它们是绕过所有纪律的一条侧门。
- 下载到哪、之后清不清，全靠调用方自己想着。

## 动机

把 FTP 接入**同一套纪律**：地址用一种 `target` 表达（与压缩包、本地并列），
写操作走同样的凭据，删除同样不执行。同时让**凭据只在内存里**。

## 非目标

- **不做** SFTP / FTPS 的完整参数体系（先做最常用的明文 FTP；加密传输属**待议**）。
- **不做**目录同步 / 镜像。
- **不做**断点续传。
- **不做**凭据的持久化（不写配置文件、不写凭据管理器）——**服务不替用户记密码**。
- **不做**多协议（WebDAV / SCP）——加协议是把口子越开越大。

## 设计

### 会话是"另一类 target"

```
login(host, port, user, password)  → 返回 ftp:<session> 句柄
   ↓
read / list / copy / delete（target = ftp:<session>，path = 远端路径）
   ↓
logout(session) 或者不记得句柄时 logout()（关掉全部）
```

**地址的三种形态**统一在 `target` 一个参数上：空 = 本地；`ftp:` 前缀 = 会话；其余 = 压缩包路径。
**认不出来就报错，不降级到本地**（[F4](../F4-不知道自己在哪层目录.md) 的一致性）。

### 凭据的处理

- **只存内存、不落盘、日志里打码、列表里打码**。
- 进程退出即失效——不存在"下次还能用"的持久凭据。
- 会话有**上限**（避免无限登录）与**空闲超时**。

### 远端写操作比本地更保守

| 操作 | 行为 |
|---|---|
| 读 / 列 | 正常 |
| 写（上传、覆盖） | 走凭据；目标已有内容时**要凭据**（[F1](../改动的可信度.md) 的口径） |
| **删除** | **一律不执行**——远端没有回收站，删了不可恢复（[F2](../改动的可信度.md)） |
| 移动（远端 → 远端） | 需要"拷贝 + 删源"，**删源这一步不做**，所以远端内部的移动实际上是**拒绝**的 |

### 预期返回什么 / 不返回什么

- **返回**：登录后返回**句柄**；文件操作返回与本地同样的形态（清单、内容 + 标识、落盘路径）。
- **返回**：远端操作的结果里要区分"远端本来没有"与"取不到"。
- **不返回**：密码（任何情况下）；不返回凭据的持久化提示。
- **不返回**：远端目录的完整树（除非显式要求递归，且要限量）。

## 备选

- **可用的**：每条命令带一次凭据（不用会话）。**不想实现**——那会把密码反复带进上下文，
  而且每次都要重新握手。
- **可用的**：用命令行 `curl` 包一层。**不想实现**——那正是现状的坑（编码、被动模式、凭据进日志）。
- **走不通的**：把远端当本地一样支持全套写操作（含删除）。
  **不想实现**——远端删除不可恢复，这是刻意的拒绝，不是能力欠缺。
- **走不通的**：做"远端目录同步"。同步需要"哪边新"的判断，而远端的时间戳与时钟**不可信**；
  硬做出来会静默丢数据。

## 缺点

- **明文 FTP**：默认不做加密传输，密码在网络上是明文。这是"先做最常用的"的代价，见待议。
- **远端内部的移动做不到**（要删源，而不删源就不是移动）——这是最容易被问到的限制。
- **会话是内存态的**：进程重启后句柄全失效，要重新登录。
- **中文文件名 / 编码**：FTP 服务器之间的编码约定很乱，现在的处理是"按服务器给的字节处理"，
  遇到乱码只能如实显示。
- **一次只能看到一个会话的状态**：没有"列出当前所有会话"的工具
  （`logout` 不带参数能关掉全部，但看不到有哪些）。

## 待议

- **会话上限与空闲超时**：现在分别是 16 与 10 分钟，两个数都是拍的。
- **要不要支持 FTPS / SFTP**：加密传输是刚需还是加分项。
- **默认端口**（21）之外要不要支持自定义端口段。
- **`logout` 不带参数时**：关掉全部——但调用方不知道关了几个（返回里说了数量，但没有名字）。
- **远端目录的递归 `list` 上限**与本地是不是同一套。
- **上传大文件要不要限速 / 进度**。

## 影响

有了它，AI 可以：

- **在一个会话里连着做多次远端操作**，而不用每次重新拼命令。
- **把远端的东西下载下来**（然后走 [P-RS-01](P-RS-01-本地读.md) 的范围读）或者**传上去**。
- **将就着做**"远端目录盘点"：`list` 出清单，判断哪些是旧文件（但删不了——那是设计）。

它会催生什么：**"另一类存储"这个抽象**——压缩包、FTP、本地都用同一个 `target` 表达，
将来加第四种（例如某个云盘）就是加一种 `target`，而不是加一批工具。
它会挡掉什么：不需要再考虑"让 agent 用命令行摸 FTP"——那正是凭据进日志的途径。

## 适用

**以下情况它就不管用了：**

- **宿主自己带 FTP 客户端**（有些编辑器能做远端编辑），这层就重复了。
- **需要加密传输**：FTPS/SFTP 现在没做。
- **需要删远端文件**：设计上就是拒绝的。
- **要读的是"远端压缩包"**：远端只能读与搬运，**不能改包**（组合场景归各自的设计，不单独成痛点）。
