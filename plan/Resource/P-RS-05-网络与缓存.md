# P-RS-05 · 网络与缓存（`fetch` / `cache`）

| | |
|---|---|
| **项目** | `src/ZMS.MCP.Resource` |
| **痛点** | [F3](../F3-同一地址读两次.md)、[F11](../F11-读大文件里的几行.md)（同一件事的网络版） |
| **状态** | 已实现 |
| **工具** | `fetch`、`cache` |

## 摘要

取一个 http 地址的内容（或者把它下载到磁盘），以及**管理取回来的东西**：
列出手上有哪些、按标识读出来、按标识落到磁盘。核心是"**上下文里只留一个短标识，不留一整份内容**"。

## 现状

- 宿主取网页是**取一次、进一次上下文**：同一地址第二次取，网络照跑、内容照进上下文。
  一次会话里同一页可能进三遍（横向对比一遍、确认一遍、写总结一遍）。
- **长内容全进上下文**：200 KB 的 JSON 进来，真正有用的可能只有一行。
- 取回来的东西**留不住**：新会话要重新取（[F3](../F3-同一地址读两次.md) 里的 C3）。
- 下载到磁盘之后**没有"给标识 + 按需取片段"**这条链：文件下来了，还是得整份读进来。
- "取过的这份还算不算新鲜"没有概念——要么永久以为它是对的，要么每次都重取。

## 动机

把"取回来"与"用起来"解耦：

- 取回来 → 内容留在服务这边，上下文里只放一个**短标识**；
- 要用 → 按标识**读出来一段**，或者**落到磁盘**之后用范围读（与 [P-RS-01](P-RS-01-本地读.md) 接上）。

## 非目标

- **不是为了"给对端省流量"**：限流一类是礼貌，不是这条的诉求。命中缓存是"这边不用再跑一遍"。
- **不做**缓存协商（`ETag` / `If-Modified-Since`）：这条只说"取过的别再取"。
- **不做**网页正文提取（把 HTML 转成可读文本）——那是解析，另一件事（渲染那半见 [P-RS-07](P-RS-07-浏览器.md)）。
- **不做**认证与 Cookie 管理（登录态、会话保持）。
- **不做**给下载**断点续传**。

## 设计

### `fetch`：取内容 / 下载，两种用途

| 给的参数 | 行为 | 进缓存吗 |
|---|---|---|
| 不给 `targetPath` | **取内容**：内容进缓存，返回一个标识 | **进**（内容缓存） |
| 给了 `targetPath` | **下载**：写到那个路径 | **不进**——原件已经在磁盘上了，还留一份没意义（只留一条元信息） |

重试与超时：**重试上限 3 次、超时 15 秒**。响应超过一次交付量时截断，并给出账。

### `cache`：三个动作，看一个参数

| 给的参数 | 行为 |
|---|---|
| 标识为 `null` | **列出**手上有哪些：每条一行 `工具 \| 参数 \| 时间 \| 标识` |
| 给了标识 | **读出**那一条的完整内容 |
| 标识 + 路径 | **落盘**到那个路径（之后可用范围读看其他部分） |

**注意 `read` 不命中缓存**：读本地文件时缓存没有价值（文件就在那儿），而且"命中"会让
"我读到的是不是最新的"变得可疑。所以 **`read` 只记录、不命中**；缓存要靠显式来取。

### 缓存是什么形态

- 落的盘：**`%LOCALAPPDATA%\ZMS.MCP\cache`**（可用环境变量覆盖），**不写进被操作的项目**。
- 生命周期：**TTL 7 天**、**总量上限 64 MB**（超出按最近最少使用淘汰）。
- 过期怎么知道：返回里**注明这次是"刚取的"还是"从缓存拿的"**，过期条目由启动时的异步扫描清掉。

### 预期返回什么 / 不返回什么

- **返回**：内容（截断时给出"全文多少、给了多少"）+ **标识**；下载时返回落盘路径；
  列缓存时返回清单。
- **返回**：这次是命中还是新取。
- **不返回**：命中缓存时**不重复返回**"这是哪来的"（清单里有）。
- **不返回**：对端的状态码全貌（只区分"成功/失败"，失败时给出原因）。

## 备选

- **可用的**：让 `read` 也命中缓存（同一份文件直接给缓存内容）。**不想实现**——见上面那条"不命中"。
- **可用的**：缓存**永不落盘**（只在内存里）。**不想实现**——跨会话复用正是痛点之一（C3），
  不落盘等于每开一个新会话都要重取。
- **走不通的**：缓存按 **URL** 存（不按内容）。同一份内容可能来自不同 URL，
  同一个 URL 的内容也可能变；而且"按 URL 存"意味着要判断"这个 URL 现在还算不算同一份"，
  那就回到了缓存协商，而那是非目标。
- **走不通的**：把渲染结果也塞进这个缓存。渲染是一次性的现场（见 [P-RS-07](P-RS-07-浏览器.md) 的设计），
  缓存会让人以为"这页长这样"是稳定的。

## 缺点

- **`read` 与 `cache` 的分工要说两句才明白**：为什么读了不命中、要看得专门去拿——
  这是设计取舍，但对调用方是解释成本。
- **缓存没有"我这次读到的是哪一版"的语义**：标识指向的是内容，不是"某个时刻的状态"。
  所以它不能用来做 [F1](../改动的可信度.md) 那种凭据（凭据是**另一套**：内容指纹 + 元数据）。
- **TTL 与容量是拍的**：7 天 / 64 MB 没有依据。
- **落盘是"复制一份"**：`cache(key, path)` 之后磁盘上有两份（缓存里一份、落盘处一份）。
- **限流只覆盖下载**：额度 `10 MB`、每分钟恢复 `1 MB`，且**只作用于给了 `targetPath` 的那条路**——
  "取内容"那条路没有限流。批量抓页面仍会把对端打死。

## 待议

- **TTL（7 天）与总量上限（64 MB）**：两个数都是拍的。超出按 LRU 淘汰，但"多久扫一次过期"也没定。
- **缓存落点**：`%LOCALAPPDATA%\ZMS.MCP\cache` 与 `Csharp` 的拟定数据库、`Resource` 的追踪表
  是不是该**放在同一个根目录下**（现在各写各的）。
- **一次交付的字符上限**与 [P-RS-01](P-RS-01-本地读.md) 是不是同一个数（现在分开定义）。
- **`cache` 列出多少条**：条目多时要分页（现在没有分页）。
- **那两个限流数字**（`10 MB` 额度 / 每分钟恢复 `1 MB`）是拍的；要不要也管"取内容"那条路。
- **缓存里的内容要不要压缩**（省磁盘、费 CPU）。

## 影响

有了它，AI 可以：

- **一份长内容只进一次上下文**，之后按标识取片段。
- **跨会话复用**取过的内容。
- **将就着做**"接口快照对比"：今天取一次、明天取一次（如果缓存过期或换个描述），
  两次的标识不同就说明内容变了——但它**不是**一个正经的"监控"。

它会催生什么：**`read` 与 `cache` 的落盘链**（读缓存 → 落盘 → 用范围读看其他部分）——
这条链让"大内容"有了完整的使用路径。
它会挡掉什么：不需要再考虑"让 agent 自己把内容存文件再读"那套民间做法。

## 适用

**以下情况它就不管用了：**

- **宿主自己带内容缓存**：如果宿主取网页时会去重、并把内容留在一个可引用的地方，
  这一层就重复了。
- **内容需要实时**：缓存天生会给出"一段时间前"的东西。要求新鲜的场景（价格、状态页）不该走它。
- **需要认证的地址**：不做 Cookie/登录态，摸不到墙内的东西。
- **超大文件**：走 `targetPath` 下载（不进内容缓存）才合理，取内容那条路会被一次交付量截断。
