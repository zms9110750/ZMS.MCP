# P-RS-01 · 本地读（`read` / `list`）

| | |
|---|---|
| **项目** | `src/ZMS.MCP.Resource` |
| **痛点** | [F11](../F11-读大文件里的几行.md) |
| **状态** | 已实现 |
| **工具** | `read`、`list` |

## 摘要

读一个文件里的**一段**（按行/字符范围，或给一个正则取其附近），列一个目录里的东西（带属性、可递归、可按层限量）。
它解决的是"看一小段却要把整份搬进上下文"，以及"这个文件是什么编码、多大、什么时候改的"。

## 现状

宿主（编辑器 + agent）读文件的基本形态是**给路径、还全文**：

- 想知道编码不是 UTF-8 的老文件里写了什么，唯一的办法是**绕道命令行**去转码再读——
  而宿主那边按 UTF-8 解出来的乱码不只是"看不懂"，**写回去会把原文件毁掉**。
- 几百 MB 的日志根本没有"按段流式读"的统一手法，一次读全就爆。
- 搜到一处只在命中行有结果，要判断它是配置项还是注释里提到的，得**再读一次**取上下文。
- 文件多大、什么时候改的、什么编码，散在好几个工具里。
- 列目录大多是**平铺**的：要看一棵树得自己递归；要按"只改过的"筛选得自己写脚本。

## 动机

把"定位 + 取一段 + 知道它的元信息"合成**一次调用**，并且让范围与编码**在同一个动作里说清**。
（[F11](../F11-读大文件里的几行.md)）

## 非目标

- **不做**"内置工具的加料版"：读本地文件这件事宿主本来就有，这条的价值在**范围 / 编码 / 截断**这三样，
  不在"再多一个读文件的工具"。
- **不做**文件内容的转换（"把这份 GBK 转成 UTF-8"）——只读，不改码。
- **不做**全文搜索（那是宿主 `grep` 的活；这里的 `regex` 是"读的时候顺便筛"）。
- **不做**文件变更监听。

## 设计

### `read`：四组参数，一件事

| 组 | 参数 | 作用 |
|---|---|---|
| 定位 | `target` / `path` | 读哪儿（`target` 空 = 本地） |
| 范围 | `skipline` → `offset` / `length` / `takeline` | 跳过多少行 → 再跳多少字符、最多要多少 |
| 编码 | `encoding` | 不给就按 BOM → 严格 UTF-8 → 拒绝 |
| 搜索 | `regex` | 给正则，拿到命中处**带上下文**（命中多则上下少、命中少则上下多） |

**顺序是先按行、再按字符**（`skipline` 在 `offset` 之前）——因为"跳到第 N 行"比"跳过 N 个字符"更常用。

### `list`：三种情形

| 情形 | 得到 |
|---|---|
| 完整枚举 | 树形清单 + **目录树凭据** + 条目总数 |
| 被截断 | 只给清单，写明被截断，**不给凭据** |
| 指向一个文件 | 给这个文件的元信息 + **它自己的凭据** |

**按层限量**：`depth`（0 = 只当前层）与 `limit`（每层最多几条）。

### 预期返回什么 / 不返回什么

- **返回**：内容 + （读完整份时）**凭据**。范围读、或超上限被截断时**不给凭据**——
  只读了一段不算看过全貌（与 [F1](../F1-别人改了文件.md) 的纪律一致）。
- **返回**：截断时的**账**——"全文多少字符、这次给了多少、还剩多少"。
- **不返回**：把整份塞进来再说"我截断了"（那正是这条痛点）。
- **不返回**：目录里每个文件的内容（`list` 只给名字与属性）。

## 备选

- **可用的**：把"读范围"做成宿主的参数（`read_file(offset, limit)`）。宿主确实有——但它**只按行**、
  不解决编码、不给截断账、也组合不了"搜索 + 上下文"。
- **可用的**：`file://x.txt?offset=100` 那种 URI 风格（把范围编进地址）。
  **不想实现**——地址里塞参数会让"这是个路径还是个 URI"变模糊（`target` + `path` 分开已经够清楚）。
- **走不通的**：让 `read` 也**命中**缓存（读同一份文件直接给缓存的内容）。这条试过并**放弃了**：
  读本地文件时缓存没有价值（文件就在那儿），而"命中"会让"我读到的是不是最新的"变得可疑。
  现在的做法是 **`read` 只记录、不命中**，要看缓存显式去 `cache` 拿。
- **走不通的**：按字节给范围（而不是行 + 字符）。实测里调用方想的是"第 100 行往下"，
  按字节算它得自己换算，算错就是读歪。

## 缺点

- **参数多**。`read` 有五组可选参数，`[Description]` 写全了很长；调用方要学会"什么时候用哪个"。
- **"不给凭据"这件事藏得深**：范围读之后想改文件，得先整份读一次才能拿到凭据——多一步。
- **`regex` 与"范围"的相互作用**：同时给 `regex` 和 `offset` 时，先筛还是先切？现在的语义是
  "先按行切、再筛"（见待议）。
- **`list` 的"目录树凭据"依赖整棵树能枚举完**：被截断时它没有凭据，于是"删一个目录"就得先 `list` 到不截断为止。

## 待议

- **一次交付的字符上限**（现在是 16000 字符）——为什么是这个数，没有依据；它是"上下文能承受"的估计。
- **`list` 每层最多几条**：现在默认 200、递归 1 层降到 100、2 层 50、之后 20。这套递减规则是拍的。
- **树形凭据的门槛**：整棵树能塞进多少才给凭据（现在是"不被截断且能塞进一次交付量"）。
- **`regex` 的上下文档位**：命中 >20 只给行号、>5 给上下 1 行、≤5 给上下 3 行。这三档也是拍的。
- **`encoding` 认哪些名字**：只认标准名字，还是也认中文别名（"gbk" / "gb2312"）？
- **`skipline` 与 `offset` 的顺序**要不要可配置（现在是固定"先按行"）。

## 影响

有了它，AI 可以：

- **看一眼就能判断**：`list` 给出树 + 属性，不必再 `ls` 三次叠起来看。
- **在几百 MB 的日志里找一处并读它周围**（以前这件事做不到）。
- **不毁掉非 UTF-8 的老文件**（读得对，写回也用同一个编码——见 [P-RS-02](P-RS-02-本地写.md)）。
- **将就着做**"目录 diff"：两次 `list` 的输出对比（但没有专门的 diff 工具）。

它会催生什么：**`cache` 的落盘用法**（`read` 只记录不命中，缓存真正被用起来是靠"从来取"）。
它会挡掉什么：不需要再考虑"让宿主读文件时支持编码"这条提示词工程。

## 适用

**以下情况它就不管用了：**

- **宿主自己给到了范围 + 编码**：如果编辑器的读文件已经支持"按行/按字符取一段 + 指定编码"，
  这条的增量只剩"截断账"与"搜索 + 上下文"。
- **文件大到连一段都读不动**：现在的实现是"打开文件、跳到位置、读一段"——这已经能应付几百 MB，
  但对**流式输出**（正在被写、永远在增长的文件）无能为力。
- **编码不是它认得的那些**：认不出来就拒绝，不猜——遇到少见的编码（各种 EBCDIC 变体之类）它直接放弃。
