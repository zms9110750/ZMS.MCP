# P-RS-08 · 区间抽取（`pick_random`）

| | |
|---|---|
| **项目** | `src/ZMS.MCP.Resource` |
| **痛点** | **没有对应痛点** —— 它是从被移除的老项目 `ZMS.MCP.Cli` 迁过来的 |
| **状态** | 已实现 |
| **工具** | `pick_random` |

## 摘要

从 `名称:点数` 的池子里反复随机抽取，直到抽出的**项数**落在给定区间、**点数和**也落在给定区间。
支持有放回 / 不放回，池子可以写在参数里、也可以来自一个 JSON 文件。

## 现状

这个能力原本在 `ZMS.MCP.Cli`（一个被四个新项目取代的老项目）里，叫 `PickRandom`。
老项目其余能力在四个新项目里都有对应（http、nuget、归档、uri 协议层），
或者本身就是没实现的 stub；只有这一项**没有对应物**，所以在移除老项目之前把它迁了过来。

宿主侧没有等价物：模型自己"随机挑几个"是不可靠的（它会挑出规律、会回避看起来奇怪的组合），
而这类抽取要的是**均匀**。

## 动机

**如实说：这一条不是从痛点来的。**

按 `plan/README.md` 的判据，提案应当能指回一条痛点。这一篇指不回去——
它的来历是"老项目要删、这里面有一项没地方去"。之所以还是收进来，是因为：

- 它**已经写在代码里**，给它一篇提案能把"为什么它在这儿"说清楚；
- 将来如果有人问"`Resource` 里怎么有个抽取工具"，答案不该只存在于 git 历史里；
- 它的**定位**本身是个决定：这类"算一下"的能力要不要放进 MCP。

如果判断是"这不属于 MCP 该做的事"，那它该被删掉，而不是留在提案里。

## 非目标

- **不做**骰子表达式（`4d6` / `2d20t` 那套）——那是另一个独立工具（`Utils.SingleExe` 里的 `dice`）的事。
- **不做**洗牌、排序、抽样统计（样本量、置信区间）。
- **不做**从文件里抽行（"从这份日志里随机取 10 行"）——那是另一个能力，虽然长得有点像。
- **不保证**"按权重"（点数在抽取里**只是一个约束维度**，不是被抽中的概率权重）。

## 设计

### 表达式

```
(2,4)[5,8]{甲:3,乙:2,丙:4}      项数落在 2~4、点数和落在 5~8
(3)[7]{甲:3,乙:2,丙:2}          两项各自相等（简化写法）
(2,4)[5,8]{file://pool.json}    池子来自 JSON 文件（{"甲":3,"乙":2}）
```

- 全角逗号与全角冒号也认（`甲：3，乙：2`）。
- `single = true` 是**不放回**：抽过的项不再出现。

### 算法要点

池子按**点数分组**，每组的项在内部连续存放。每次抽取先算出"还可行"的点数区间
（由"还剩多少点、还能抽几项"反推），在这个区间里随机取一个点数，再从那一组里随机取一项。

**不是"先随机抽、再不满足就重来"**——那样在约束紧的时候会抽不出来。

### 预期返回什么 / 不返回什么

- **返回**：抽中的项（逗号分隔）+ 点数和，例如 `甲, 乙 = 5`。
- **不返回**：抽取过程的中间值（哪个点数被选中过、试了几次）。
- **不返回**：池子本身（调用方给的，它知道）。

## 备选

- **可用的**：直接删掉它（"这不属于资源访问"）。这是**完全站得住的选项**——
  见"动机"那节。留着它是因为它是既有能力，不是因为它必须在这儿。
- **可用的**：把它并进 `Workflow` 或另开一个小项目。**不想实现**——
  为一个工具开一个项目，成本大于收益。
- **走不通的**："先随机抽、检查约束、不满足就重抽"。约束紧时（例如"必须正好 3 项、正好 7 点"）
  随机命中的概率极低，会一直重试。
- **走不通的**：按点数当**权重**抽（点数越大越容易被抽中）。
  那样"点数和落在区间"这件事就不成立了——两件事只能选一件。

## 缺点

- **它与 `Resource` 的主题不符**：这个项目是"资源访问"（文件、网络、压缩包、FTP、浏览器），
  而它是"算一下"。放在这里**是一个妥协**。
- **没有痛点支撑**：按项目自己的判据，它不该是一篇提案。
- **只在被抽出来的那一刻有意义**：它不读也不写任何东西。
- **"点数"这个名字很窄**：实际上它就是一个"权重/代价"维度，叫点数只是因为它来自掷骰子的场景。

## 待议

- **它该不该留在仓库里**（这是最主要的一条）。
- **要不要支持"按权重抽"**（点数当概率），以及那与"点数和落在区间"怎么共存。
- **抽取次数上限**：约束不可行时现在是抛错。要不要设一个重试上限、超了就报"这次约束抽不出来"。
- **池子上限**（几千项时的表现）。
- **`file://` 池子的路径**要不要走工作区边界检查（现在**不走**——它在这儿只被当作一层解析，
  但"读文件"这件事按理该受 [F4](../F4-不知道自己在哪层目录.md) 管）。

## 影响

有了它，AI 可以：

- **做一次均匀的随机抽取**（例如"从这几个人里挑几个"），而不靠模型自己选。

它会催生什么：**"这类算一下的小工具要不要进 MCP"这个讨论**。
它会挡掉什么：没有。它是个孤立能力。

## 适用

**以下情况它就不管用了：**

- **宿主自带随机能力**：有些宿主会提供一个 `random` 之类的工具，那这条就重复了。
- **需要真正的随机源**：它用运行时的随机数，不做密码学强度的随机（不该用它生成密钥、令牌）。
- **一次性的、规则复杂的抽取**：表达式只覆盖"项数 + 点数和"两个维度，
  更复杂的约束（"甲和乙不能同时出现"）它表达不了——那种该写代码。
