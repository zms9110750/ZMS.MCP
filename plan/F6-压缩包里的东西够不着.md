# F6 · 压缩包里的东西，不解压就够不着

| | |
|---|---|
| **状态** | 已解决（`Resource` 的压缩包按需读 + 拟定态写） |
| **涉及** | Resource |
| **相关** | 独立（与 F1 的交叉——"改包时包被外部改过"——归到提案的设计里，不单独立条） |

## 背景

zip / 7z / tar.gz 到处都是：发布产物、备份、别人发来的东西、NuGet 包本体。
AI 经常只需要看**里面一个文件**。

## 现状

- 要看里面一个文件，只能**整份解压**：几十 MB 的包解开占满磁盘，看一行就走，剩下全留着。
- 解压出来的东西**散在磁盘上**，还得记得清；忘了就变成下一轮的噪音。
- **要看包里的目录结构**（有哪些文件、多大）也得先解开——而这件事纯读元数据就够了。
- **往包里放一个文件 / 删一个文件**更是没有手段：解压 → 改 → 重新打包，中途失败就得到一个半成品。
- 不同格式要用不同的第三方工具，各有各的命令行。

## 期望

- **看**：列出包内条目（路径、大小、时间），读某一条的内容——都**直接读那个包**，不落盘、不展开。
- **写**：把"改哪几条"先攒成一份**拟定**，确认后**一次性重写整包**（先写临时文件、再原子替换），
  中途失败不留下半成品。
- 正式动包之前要先"追踪"它，之后的改动都记在这份拟定上；**看包不需要追踪**。
- 全流程遵守 F1（改已有条目要带凭据）与 F2（包内删除也算删除，同样走确认）。
- 支持常见格式：zip / 7z / tar.gz / tar+zstd。

## 验收

- 读一个包里第 N 个条目，**磁盘上不出现解压产物**。
- 列包内结构时，不读任何条目的内容。
- 改包的拟定在没有确认之前，**原包一个字节没动**。
- 拟定期间包被外部改过 → 确认时**拒绝落盘**。

## 不包含

- **不做**"包内文件的部分更新"（改一个字节就地写回）：多数格式不支持，且会让整个包的结构失效。
- **不做**跨包移动文件（从 A 包搬到 B 包）——先取出来、再放进另一个，两步已有。
- 不做加密压缩包（带密码的 zip / 7z）的读写。
- 不做"增量打包"（只把变化的部分重写）——目前是整包重写，包大时这是**待议**里的代价。
