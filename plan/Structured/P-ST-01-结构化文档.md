# P-ST-01 · 结构化文档（`read_structured` / `edit_structured`）

| | |
|---|---|
| **项目** | `src/ZMS.MCP.Structured` |
| **痛点** | [F10](../F10-结构化文档只能整份重写.md)、[F1](../F1-别人改了文件.md)、[F9](../F9-分不清名字指哪个符号.md)（它的反面：这里没有符号，只有路径） |
| **状态** | 已实现 |
| **工具** | `read_structured`、`edit_structured` |

## 摘要

按**路径**读写结构化文档：json / xml / yaml / toml / ini 五种格式，用一套「定位表达式」指出要动哪一处，
改完之后**其余原样**（缩进、引号、注释、键序都不动）。

## 现状

宿主对这类文件只有**整份读、整份写**：

- 改一个值要把整份内容搬进上下文。几百行的 yaml 里全是与这次改动无关的行。
- **写回时格式会变**：缩进、引号风格、键的顺序全凭序列化器的心情，于是 **diff 变成整份**——
  评审时看不出到底改了什么。
- **注释最惨**：多数解析器读的时候丢掉注释，写回时注释就没了。而配置文件里满是注释。
- 四种格式各有各的语法，AI 得记住四套（加上 xml 就是五套）。
- 没有 schema、没有校验，改错了要到运行时才知道。

## 动机

把"改一个值"从"整份重写"变成"**改那一处**"（[F10](../F10-结构化文档只能整份重写.md)）：

- 只读要读的那一段；
- 只改要改的那一处，**其余原样**——这一条是核心，它决定了 diff 能不能看、注释能不能活；
- 与 [F1](../F1-别人改了文件.md) 一致：改已有的文件要凭据。

## 非目标

- **不做**"重新格式化整份文档"——那正是这条痛点要避免的。
- **不做** schema 校验（json schema / xsd 的合规检查）：那是另一件事，且每种格式一套。
- **不做**结构化查询语言（jq 那套语法）：路径写法要**足够简单，让 AI 一次写对**。
- **不做**新建文档（没有"原样保留"可言，新建直接写文件就行——见 [P-RS-02](../Resource/P-RS-02-本地写.md)）。
- **不做**远端文档（FTP 上的 json 要先下载下来再读）。

## 设计

### 一套定位表达式，五种格式

| 格式 | 扩展名 | 定位写法 |
|---|---|---|
| json | `.json` | JsonPath：`$.a.b[0]`、`$..name` |
| xml | `.xml` | XPath：`/root/item[1]`、`/r/x/@v` |
| yaml | `.yaml` / `.yml` | 点路径：`a.b.c`、`a.b[0]` |
| toml | `.toml` | 点路径：`a.b.c` |
| ini | `.ini` | `section.key`（顶层键直接写 `key`） |

**`point` 为空 = 整份文档**（读 = 整份内容，写 = 整份替换）。
**格式判定**：显式 `format` 优先 → 否则按扩展名 → 都不认识就**报错，要求显式给格式**（不猜）。

### 读：`read_structured`

- `point` 非空 → **只返回那一处**，**不带凭据**（凭据是整份结构的句柄，只读了局部就没有它）；
- `point` 为空 → 返回整份内容，**并附加凭据**；
- `depth`（展开深度）与 `length`（最多展示多少字符）都会**明写被截断**：
  "此处还有 N 字符未展开" / "（已省略 N 字符）"。

### 写：`edit_structured`

**先重新读盘、比对解析后的结构**（不是字节）：缩进、空白、换行、注释、对象内的键顺序**忽略**；
键名、值、数组顺序、嵌套层级**都算**。不一致就拒绝写——这是 [F1](../F1-别人改了文件.md) 在结构化文档上的形态。

**匹配结果 × 是否给 `value`，组合出四种动作；四个开关是它们的许可：**

| 匹配结果 | `value` | 需要的开关 | 动作 |
|---|---|---|---|
| 命中 | 有值 | `update` | 改写 |
| 命中 | `null` | `remove` | 删除（父容器留着，哪怕变空） |
| 没命中 | 有值 | `insert` | 插入 |
| 没命中 | `null` | — | 报错（没有动作可做） |

**开关没开时不写，并回报匹配到的内容**——要求确认后再来一次。
这条是为了**防止"我以为在改、其实在插"**：没命中时的 `insert` 与命中时的 `update` 是不同的动作，
调用方必须明确说出它想干哪个。

### 预期返回什么 / 不返回什么

- **返回**：那一处的内容（读）/ 改了几处、改之前是什么（写）/ 截断的账 / 凭据。
- **返回**：多命中但没开 `multi` 时，**列出全部命中路径**（要么收紧表达式，要么打开 `multi`）。
- **不返回**：整份文档（除非 `point` 为空）。
- **不返回**："已写入"三个字——新旧值相同时回"值没有变化，未写入"。

## 备选

- **可用的**：用现成库的 **round-trip 能力**（读进来、改一处、序列化回去）。
  **不想实现**——实测里它会把注释丢掉、把键序重排、把引号风格换掉（[F10](../F10-结构化文档只能整份重写.md) 的痛点就是它）。
  我们要的是"只动那一处"，而这需要**按语法树原位改**、不是"解析成对象再序列化"。
- **可用的**：只做读、不做写。**不想实现**——改一个值是最高频的需求。
- **可用的**：只支持 json 与 yaml（最常用的两种）。**不想实现**——xml / toml / ini 的改法是一模一样的形状，
  少一种就多一次"这个我改不了"。
- **走不通的**：做**统一的抽象语法树**（把五种格式映到一种中间表示再写回）。
  它们的"位置语义"差别太大（xml 有属性与文本节点、ini 有节、toml 有表数组），
  强行统一之后每一种的细节都会丢——而细节正是"其余原样"要保的东西。
- **走不通的**：**只靠正则/文本替换**改这些文件。yaml 的缩进即语义、json 的嵌套与转义，
  文本替换在稍微复杂一点的文档上就会改错地方。

## 缺点

- **四个开关很啰嗦**：一次简单的"改个值"要带 `update = true`。
  这是"防误插"的代价——没命中时到底是插还是报错，必须由调用方说清楚。
- **同一次调用只能用一个动作**：想"改一处 + 删一处"要两次调用（`multi` 只解决"同一个动作作用在多处"）。
- **每种格式的定位写法不一样**：调用方得知道 JsonPath 与 XPath 的差别，
  这与 [P-CS-01](../Csharp/P-CS-01-符号查询.md) 的"名字怎么写"是同一类负担。
- **xml 改元素要传完整片段**：实测踩过——传纯文本 `"2"` 会导致解析失败，
  而正确写法是 `<a>2</a>`。这条没写进工具介绍时，第一次用必然失败一次。
- **凭据按"解析后的结构"比对**：这意味着**只改了缩进/注释**的编辑**不会**被检测为冲突
  （这是有意的：格式化不该算冲突），代价是"别人改的注释"会被静默覆盖。
- **只在少数样例上验证过**：五种格式的边角写法（yaml 的锚点、toml 的表数组、ini 的重复节）
  覆盖得不够。

## 待议

- **`depth` 与 `length` 的默认与上限**：现在 `length` 默认 500、上限 5000，两个数都是拍的。
- **`depth` 的默认**（0 = 不限）：不限在大文档上很危险。
- **凭据要不要带内容段**：现在是"结构指纹"，没有内容段（与 [P-RS-02](../Resource/P-RS-02-本地写.md) 的口径不同）。
- **`multi` 与多个不同的值**：现在多命中时每个命中处写**同一个** `value`。
  要"每处不同"就只能分开调用——这条路要不要开。
- **yaml 的锚点（`&name`）与合并键**：锚点写回去会坏，现在的处理是拒绝（说清"先手工展开再来改"）。
  要不要支持。
- **xml 的命名空间前缀**：定位表达式里怎么写带前缀的节点，现在没有明确定义。
- **新建文档**：现在不做（要新建就直接写文件）。要不要给一个"按格式生成一份初始化文档"的入口。

## 影响

有了它，AI 可以：

- **改一个值而不惊动其余**：diff 只有那一行，注释原位不动——这是评审能看得下去的前提。
- **只读需要的那个节点**，而不是把整份配置搬进上下文。
- **将就着做**"配置审查"：按路径读几个关键节点，够回答"这个开关开着吗"。

它会催生什么：**`Csharp` 那边改 `csproj` 的一个属性**（`edit_project_metadata`）与它在同一个交叉点上
——两个工具都在"改 XML 的一个节点"，一个懂项目语义、一个懂 XML（见 [P-CS-04](../Csharp/P-CS-04-工作区与解决方案.md) 的待议）。
将来这两条路会合成一条。
它会挡掉什么：不需要再考虑"给模型一段 json 让它整份重写"——那正是 diff 变整份的原因。

## 适用

**以下情况它就不管用了：**

- **宿主有自己的结构化编辑**：如果编辑器侧能"按路径改一个节点、保住格式"（VS Code 的 json 编辑接近这个），
  这一层就重复了。
- **要改动的是**结构本身（把 `a.b` 从对象改成数组）：*这是"改值"不是"改结构"，
  定位表达式描述不了"把这里整个换一种形状"——那种情况还是得整份写。
- **格式不在支持列表里**：`.jsonc` / `.hjson` / `.properties` 都不认，报错要求显式给格式，
  而给了也不认识——就直接帮不上忙。
- **文档大到一次读不动**：`depth` / `length` 能截断展示，但**要改文档还是得整份解析**。
