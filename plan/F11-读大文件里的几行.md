# F11 · 读一份大文件里的几行，却整份搬进上下文

| | |
|---|---|
| **状态** | 已解决（`Resource` 的 `read`：范围参数 + 编码 + 截断与凭据） |
| **涉及** | Resource |

## 背景

AI 干活时最常做的一件事是：**在一个大文件里找到一处，读它周围那几行**。
配置文件几百行、日志几万行、导出的数据几十万行——真正要看的往往是一小段。

## 现状

- 宿主的读文件是"**给路径、还整份**"。于是实际流程变成两步：先搜（拿到行号）、再读（按行号取一段）。
  两步之间还容易读错位置——文件一边在被改。
- **非 UTF-8 的文件读不了**：按 UTF-8 解出来是乱码。乱码不只是"看不懂"，而是**写回去就会毁掉原文件**
  （把一份 GBK 的文本按 UTF-8 重写，中文全成问号）。
- **几百 MB 的文件根本取不进来**：取不动，也没有"一次取一段、接着往下取"的统一做法。
- **想知道这份文件多大、什么时候改的、什么编码**，得另跑一条命令——而这些决定了"该怎么读它"。
- 搜到的**上下文不够**：命中一行，但只给这一行，判断不了它是配置项还是注释里提到的。

## 期望

- 一个读的动作能同时给出：**范围**（跳过多少行/多少字符、最多要几行/几字符）、
  **编码**（不指定就按 BOM → 严格 UTF-8 → 拒绝，指定了就必须解得出来）、
  **搜索**（给一个正则，拿到命中处**带上下文**）。
- **超大文件也按同一个上限走**：一次只交付那么多（几千字符），要看更多就再读一次。
- 返回里**说清这次交出去了多少**：是整份，还是截断了、还有多少没给。
- **交出去的和缓存的不一样**：只读了一段就**不算看过全貌**，因此**不给凭据**（F1 的一致性）。
  注意：**本地文件的读不写内容缓存**（进缓存的只有 `fetch` 取回来的东西，见 [F3](F3-同一地址读两次.md)），
  所以"再看其他段"就是**对同一份文件再读一次范围**，不是从缓存里取。

## 验收

- 读一份 GBK 编码的中文文件，内容正确（不是乱码）；写回时按原编码写，原文件的中文不被毁掉。
- 读一个几百 MB 的文件的一段，能拿到那一段，不因为"文件太大"整个失败。
- 只读了一段时，不返回凭据；读完整份时才返回。
- 用正则搜到的命中处，每条带上下文（命中多时上下少、命中少时上下多）。

## 不包含

- 不做"把文件转成别的编码"——只读和写回，转换是用户自己的事。
- 不做语法高亮、不做行号注释、不做 diff。
- 不做文件监听（"它变了就告诉我"）——那是 F1 的另一半，且需要长连接。
