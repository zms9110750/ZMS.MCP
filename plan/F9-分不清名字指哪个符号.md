# F9 · 改代码时，分不清"这个名字"指的是哪个符号

| | |
|---|---|
| **状态** | 已解决（`Csharp` 的 `symbols` + `rename_symbol`；`Structured` 是它的反面（文本层）） |
| **涉及** | Csharp |
| **相关** | 独立。它与 F1 不同：F1 是"文件被别人改了"，这条是"我在同一份文件里改错了地方" |

## 背景

AI 改代码时手里只有**文本**。而 C# 里的"同一个名字"在语义上可能指好几个东西：
同名重载、嵌套类型里的同名成员、扩展方法、局部函数、以及**注释和字符串里出现的同名文字**。

## 现状

- 文本替换做不到语义判断。改一个方法名会**连带改掉**：
  - 同名但**不同**的符号（另一个类里也叫这个名字的方法）
  - **注释里**提到的名字
  - **字符串字面量**里的名字（而这常常是要保留的：反射用的名字、配置键、日志标签）
- 反过来，**该改的地方它又会漏**：`nameof(...)`、反射用的字符串、另一个 `#if` 分支里的引用。
- "这个名字没出现在文本里"**不能**证明"没人用它"——语义上的引用文本里看不到。
- 判断"这一处调用的是哪个重载""`var` 背后是什么类型"需要重载解析与类型推断，纯文本做不到。
- 一个符号在**原文里从哪到哪**，文本工具得自己推（前面的文档注释、attribute、行尾注释算不算这个成员？）；
  而 Roslyn 的 `DeclaringSyntaxReferences` 直接给区间。

## 期望

- 有一套**按名字**（而不是按位置）的读写入口：列符号、看一个类型的结构、看一个成员的完整源码与行号区间。
- 改名是**语义改名**：只动真正引用这个符号的地方。
- 与 F1 一致：改名也要能满足"我知道我要改的是什么"（先出改动清单，确认了才落盘）。

## 验收

- 改一个方法名，**同名但不同类**的方法、注释里的名字、字符串字面量里的名字**都不动**；
  而 `nameof` 里的引用**跟着改**。
- 列出的成员带"它在原文的哪几行到哪几行"，与文件实际内容对得上。
- 同一个符号在多处声明（`partial` 类、`#if` 分支）时，得到的是**一份合并视图**，不是几份残缺视图。

## 不包含

- 不做死代码分析（"这个成员没人用"）：静态分析看不到反射，误报代价高（别人的项目在这上面栽过）。
- 不做 code fix / 自动修复诊断（`dotnet format` 更专业，宿主也能跑）。
- 不做跨解决方案的引用分析。
