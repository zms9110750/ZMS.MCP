# F12 · FTP 上的东西完全够不着

| | |
|---|---|
| **状态** | 已解决（`Resource` 的 `login` / `logout` + 远端读写） |
| **涉及** | Resource |

## 背景

FTP 还活着：公司内网的文件服务器、老设备的管理界面、共享盘、一些托管服务只在 FTP 上给文件。

## 现状

- 宿主**没有任何 FTP 能力**。想在 FTP 上读一个文件，只能在命令行里手打一串 `ftp` / `curl` 命令，
  还得手工处理凭据、被动模式、编码、以及"下载到哪、之后清不清"。
- 更糟的是**凭据进上下文**：为了一条命令，用户名密码被写进对话里。
- 读写删都没有统一形态：每次都要现编命令，且这些命令**不经过工作区边界检查**（F4）、
  也没有凭据/确认（F1/F2）。

## 期望

- 先"登录"一次，拿到一个**会话句柄**，之后所有文件操作把它带上（读 / 列 / 写 / 移）。
- 凭据**只进内存**：不落盘、不出现在日志里、列表里打码。
- 远端文件操作遵守本地那套一致的规矩：**读要凭据、删除不执行**（远端没有回收站，F2）、
  跨存储搬运要显式确认（F1）。
- 句柄可以显式注销；不记得句柄时允许"关掉全部"。

## 验收

- 登录后能用同一个句柄连续做多次文件操作。
- 返回里**看不到密码**，日志里也没有。
- 对远端的删除请求被拒绝（说明原因），而不是静默执行。
- 进程退出后凭据不再有效（不存在"下次还能用"的持久凭据）。

## 不包含

- 不做 SFTP / FTPS 的完整参数体系（先做最常用的明文 FTP；加密传输属**待议**）。
- 不做目录同步（"把本地这个目录镜像上去"）——那是另一个工具，且危险。
- 不做断点续传。
- 不做凭据的持久化保存（不写配置文件、不写凭据管理器）——这条是刻意的：**服务不替用户记密码**。
